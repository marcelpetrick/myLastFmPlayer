# UI and usability review (2026-08-04, v0.0.137)

Scope: the PyQt6 desktop UI as it exists at v0.0.137 — `my_lastfm_player/ui/main_window.py`,
`my_lastfm_player/ui/preferences_dialog.py`, `my_lastfm_player/ui/track_table_model.py`, plus the
user-facing behaviour driven from `my_lastfm_player/controller.py` and `my_lastfm_player/settings.py`.
Visual reference: `media/currentState.png` and a frame from `media/myLastFmPlayer_v0.0.127_recording.webm`.

This is a usability review, not a bug hunt. Items are ranked by how much they hurt a real user
session, not by how hard they are to fix.

## Summary

| # | Severity | Item |
|---|----------|------|
| 1 | High | Quitting deletes the fetched track list and the Last.fm session by default, without warning |
| 2 | High | The automatic bulk download cannot be stopped from the UI |
| 3 | High | No keyboard support at all: no shortcuts, no mnemonics, no accessible names |
| 4 | Medium-high | The "Fetch loved tracks" action exists but is not reachable from any menu |
| 5 | Medium | "Loved at" shows raw UTC stamps like `20090806-090753` |
| 6 | Medium | The "File" column does not show a file, and is empty for most rows |
| 7 | Medium | Errors are only whispered into a scrolling log, and the same text is shown three times |
| 8 | Medium | Fake example rows are indistinguishable from real data at startup |
| 9 | Medium | No volume or mute control |
| 10 | Low | Username and window geometry are not remembered, unlike every other preference |

## Details

### 1. Quitting deletes user data by default (High)

`AppSettings.keep_data_on_quit()` defaults to `False` (`my_lastfm_player/settings.py:97`), and
`ApplicationController._handle_quit` calls `repository.wipe()` on every close
(`my_lastfm_player/controller.py:153`). `wipe()` deletes the credentials file, the download cache,
the lookup cache and every file in `tracks_dir` (`my_lastfm_player/storage.py:80`).

So the default experience is: fetch 319 tracks, wait through a long lookup and download run, close
the window — and the next start shows an empty table, a forgotten scrobbling session, and a new
full lookup pass. The audio files survive, which makes it worse: the data that would have let the
app recognise them is exactly what was deleted.

Nothing warns about this. The only control is a checkbox labelled "Keep cached data after quitting"
inside a "Privacy" group in the preferences dialog, which the user has no reason to open.

Suggested fix: invert the default to keep data, and if the wipe-on-quit behaviour is wanted, make it
an explicit opt-in with a confirmation on the first quit that would delete something. At minimum,
say in the UI what will be deleted.

### 2. The automatic bulk download cannot be stopped (High)

After a fetch, the controller starts the YouTube lookup automatically
(`_start_automatic_lookup`, `my_lastfm_player/controller.py:1126`) and then the download queue
automatically (`_start_automatic_download`, `my_lastfm_player/controller.py:1182`). For a typical
loved-track list this is hundreds of network requests and potentially gigabytes of audio, begun
without asking.

The manual download control was removed in v0.0.130 (commit `6a95985`). The controller still
connects `download_requested` and `download_stop_requested` (`my_lastfm_player/controller.py:135`),
and `MainWindow` still declares both signals (`my_lastfm_player/ui/main_window.py:154`), but no
widget emits them any more, so `stop_downloads()` is unreachable. The only way out of a running
download is to close the application — which, per item 1, then also wipes the cache.

Suggested fix: bring back one toggle button ("Start downloads" / "Stop downloads") next to the fetch
controls, wired to the signals that already exist, and remove the dead signals if the decision is to
keep the fully automatic flow.

### 3. No keyboard support (High)

There is no `setShortcut`, no `QKeySequence`, no `setBuddy`, no `setTabOrder` and no
`setAccessibleName` anywhere in `my_lastfm_player/`. Consequences:

- No Space for play/pause, no Ctrl+Q for quit, no F5 for fetch, no Ctrl+F to jump to the filter.
- Menu titles ("Main", "Language", "Help") have no `&` mnemonics, so the menu bar cannot be opened
  from the keyboard in the usual way.
- `username_label` and `track_filter_label` are plain `QLabel`s with no buddy, so they contribute
  nothing to keyboard navigation or to screen readers.
- Tab order is whatever the construction order happens to produce.

For an app whose main loop is "filter, select, play, next", this is the change with the best
effort-to-benefit ratio in the whole list.

### 4. The "Fetch loved tracks" action is unreachable (Medium-high)

`refresh_action` is created and translated (`my_lastfm_player/ui/main_window.py:198`, `:967`) and its
enabled state is maintained by `set_fetch_enabled` (`:520`), but `_build_menus` never adds it to a
menu, and there is no toolbar. Only the tests trigger it. It is dead UI that still costs
maintenance and translation effort.

Suggested fix: add it to the Main menu (with F5), or delete it and let the Fetch button be the only
entry point.

### 5. "Loved at" shows a machine timestamp (Medium)

`_parse_api_loved_at` stores `%Y%m%d-%H%M%S` in UTC (`my_lastfm_player/lastfm.py:671`), and the model
renders that string unchanged (`my_lastfm_player/ui/track_table_model.py:167`). The user sees
`20090806-090753`. The app is fully translated into several languages, then presents its only date
column in a format no locale uses, in a timezone that is not the user's.

Suggested fix: display a localised date via `QLocale`, and keep sorting correct by returning the raw
sortable value from a separate role (for example `Qt.ItemDataRole.UserRole + 1`, with
`setSortRole` on the proxy) instead of relying on the display string.

### 6. The "File" column does not show a file (Medium)

The header says "File" (`my_lastfm_player/ui/track_table_model.py:102`) but the cell contains the
container and bitrate — "WEBM, 146 kbps" — produced by `_download_file_details` (`:227`). For every
row that is not `DOWNLOADED` the cell is empty, so in a fresh list the column is a wide blank stripe.
There is also no way to reach the actual file: no "Open containing folder" or "Copy path" in the
context menu.

Suggested fix: rename the column to "Format" or "Quality", and add the file actions to the row
context menu.

### 7. Errors are easy to miss, and status text is shown three times (Medium)

`_handle_worker_error` only calls `window.append_feedback` (`my_lastfm_player/controller.py:993`),
which appends one line to a 500-line scrolling `QPlainTextEdit`. A mistyped username, a network
failure or a yt-dlp breakage therefore looks almost identical to "nothing happened" — the line
scrolls past among dozens of routine "is now Searching" messages. There is no `QMessageBox` anywhere
in the application and no visual distinction (colour, icon, level) between routine progress and
failure inside the log.

At the same time the *same* message is displayed in three places: the progress bar text
(`set_progress` uses `setFormat(label)`, `my_lastfm_player/ui/main_window.py:724`), the status bar,
and the log. The screenshot shows this clearly — the bottom status bar repeats the last log line
verbatim, and the progress bar's percentage is replaced by prose, so the bar communicates progress
only through its fill.

Suggested fix: mark errors distinctly in the log (prefix or colour), keep a persistent
"last error" indicator, and let the progress bar show `%p%` plus a short static label rather than
mirroring the log.

### 8. Example rows look like real data (Medium)

`_set_example_tracks` puts "Example Artist — Example Track" and "Another Artist — Waiting for
implementation" into the real table at startup (`my_lastfm_player/ui/main_window.py:498`), and they
are counted: the label reads "Playlist: 2 titles". A first-time user cannot tell these from a
loaded playlist, and "Waiting for implementation" is developer language in a shipped UI.

Suggested fix: show an empty table with a one-line hint ("Enter your Last.fm username and press
Fetch"), and drop the fake rows.

### 9. No volume or mute control (Medium)

`QtPlaybackBackend` creates a `QAudioOutput` (`my_lastfm_player/playback.py:79`) and never touches
its volume; no widget, no setting, no shortcut. The user has a seek slider but must leave the
application to change the volume. For a music player this is a missing basic, not a nice-to-have.

Suggested fix: a volume slider plus a mute toggle next to the transport buttons, persisted in
`AppSettings` like the other preferences.

### 10. Username and window geometry are not remembered (Low)

Theme, language, scrobbling, cookie browser, concurrency and the randomize toggle are all persisted,
but the Last.fm username must be retyped on every start, and the window always opens at
`resize(1120, 720)` (`my_lastfm_player/ui/main_window.py:183`) regardless of how the user last sized
it. The inconsistency is what makes it noticeable: everything else is remembered.

Suggested fix: persist the last username and restore the window geometry/state via `QSettings`.

## Minor observations

- The "Artist" group box takes roughly a third of the control row and is an empty framed box
  whenever nothing is playing (visible in the v0.0.127 recording). Consider collapsing it while idle.
- `username_input.editingFinished` triggers `load_cached_tracks_for_entered_username`
  (`my_lastfm_player/controller.py:130`), so merely tabbing out of the field can silently replace the
  whole table. A side effect on focus loss is surprising.
- The row context menu offers "Retry Download" for every row, including rows that were downloaded
  successfully and rows that were never attempted.
- A context menu is the only way to retry a failed track; nothing in the UI hints that it exists.
- The preferences dialog has no OK/Apply — every change is written immediately and the only button is
  "Close". That is defensible, but the dialog should say so, since users expect Close to discard.
- Log timestamps are `HH:mm:ss` with no date, which is ambiguous for a session left running overnight.

## What works well

Worth recording, so the list above is not read as a verdict on the whole UI: the sort/filter proxy is
responsive and correct across a few hundred rows, elided text keeps long titles readable, the
dependency status line is a good piece of proactive feedback, the four themes are consistently
applied through a single palette path, and the translation coverage (including the About and license
dialogs) is unusually thorough for a project this size.
